# Layer 7: Power BI Dashboard

`TelemetrixAI_Dashboard.pbip` is a Power BI Project (PBIR + TMDL source format) built directly against `anomaly_results.csv`. No manual GUI build is required — just open it.

## Opening it

1. In Power BI Desktop, enable both preview toggles once (**File > Options and settings > Options > Preview features**): **Store reports using enhanced metadata format (PBIR)** and **Store semantic model using TMDL format**.
2. Open `TelemetrixAI_Dashboard.pbip`.
3. Click **Refresh now** on the data banner (Import mode needs one manual refresh after open).

## What's on it

**Page 1 — Overview**
- Line chart: `latency_p95_ms` over time, by component
- Column chart: anomaly count by component
- Card: average error rate %
- Table: root-cause detail (component, scenario, flagged signal, z-score, error rate) for every flagged row
- Slicers: `scenario`, `component`

**Page 2 — Signal Detail & AI Report**
- Text box: the AI-annotated narrative (from `ai_report.md` — deterministic-fallback text, since no Gemini/Ollama backend was reachable at generation time; identical structure to what Gemini would produce per `ai_annotation.py`)
- Matrix: average error rate % by component x scenario (acts as an error-rate heatmap; toggle **Format pane > Cell elements > Background color** for the literal color-scale heatmap look — one click)
- Line chart: `throughput_rps` trend over time, by component
- Slicers: `scenario`, `component`

## Re-running with fresh data

Re-run the pipeline any time and hit **Refresh** in Power BI to pull new numbers:
```bash
python metrics_collector.py --scenario normal --duration 2
python anomaly_detection.py
python ai_annotation.py   # regenerates ai_report.md; paste the new text into the textbox visual if it changed materially
```

## Data provenance

`anomaly_results.csv` now spans 2026-07-20 -> 2026-09-16 (264 rows) to demonstrate the multi-week trend view the RFP describes:

- **2026-09-16, 90 rows**: the real captured session (live Prometheus telemetry from the running OTel demo stack).
- **2026-07-20 -> 2026-09-15, 174 rows**: **synthetic backfill**, generated by `scratch_generate_synthetic_history.py` from per-component baselines matched to the real session's operating ranges, including one synthetic 3-day `checkout` degraded window mirroring the real validated incident's stats. This is simulated data, not additional real captures — it exists solely to exercise the dashboard's multi-week trend visuals ahead of having that much real history collected.
- Every row (real and synthetic alike) was scored by the same Isolation Forest pipeline (`anomaly_detection.py` / `scratch_score_without_mlflow.py`, identical logic minus mlflow tracking) — `anomaly_score`, `is_anomaly`, `flagged_signal` are genuinely model-computed, not hand-entered.
- A pre-backfill copy of the real-only 90-row dataset is kept at `anomaly_results_session_only_backup.csv`.
